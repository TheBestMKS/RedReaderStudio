# Higgs Reader Studio 0.6.0 — локальный API

В окне программы откройте **Модели / API → Запустить API**. Адрес по умолчанию:
`http://127.0.0.1:8765`. Токен можно показать и скопировать в этом окне;
он также хранится в `api-data/api-token.txt`. Для всех запросов нужен заголовок
`Authorization: Bearer ТОКЕН`. API доступен только на этом компьютере.

Без окна: `HiggsReader.exe --api --port 8765`. Журнал — `logs/reader.log`.
Одновременно запускается один сервер для одной папки программы.
Для программного завершения используйте `POST /v1/server/stop` с `{}`:
текущие фрагменты сохранятся, очереди приостановятся, сервер завершится.

## Быстрый пример (Python из поставки, дополнительных пакетов не нужно)

Запускайте пример из папки программы: `runtime/python.exe example.py`.

```python
import json
import urllib.request
from pathlib import Path

token = Path('api-data/api-token.txt').read_text().strip()
request = urllib.request.Request(
    'http://127.0.0.1:8765/v1/audio',
    data=json.dumps({
        'text': 'Здравствуйте! Здесь может быть текст целой книги.',
        'format': 'mp3',
        'settings': {'mode': 'simple', 'engine': 'piper-denis', 'max_chars': 300}
    }).encode(),
    headers={'Authorization': 'Bearer '+token, 'Content-Type': 'application/json'})
with urllib.request.urlopen(request, timeout=86400) as response:
    with Path('result.mp3').open('wb') as output:
        while chunk := response.read(1024*1024):
            output.write(chunk)
```

`POST /v1/audio` ждёт завершения и возвращает аудио с заголовком `X-Job-ID`.
Для книг предпочтительна фоновая очередь: `POST /v1/jobs` с тем же JSON
сразу возвращает `202` и объект задания с `id`.

## Методы

| Запрос | Ответ / действие |
|---|---|
| `GET /v1/settings` | Настройки по умолчанию, режимы, форматы |
| `GET /v1/models` | Каталог TTS и языковых моделей; `installed`, `downloadable` |
| `POST /v1/downloads` | `{"model":"qwen2.5-7b"}` → ID фоновой загрузки |
| `GET /v1/downloads/{id}` | `status`, скачанные `bytes`, текущий `file`, `error` |
| `POST /v1/uploads` | Загрузить образец голоса или обложку; возвращает `id` |
| `POST /v1/jobs` | Начать фоновую генерацию |
| `GET /v1/jobs` | Список сохранённых заданий |
| `GET /v1/jobs/{id}` | Состояние, `progress` (готовые фрагменты), `total`, ошибка, персонажи |
| `POST /v1/jobs/{id}/stop` | `{}` → остановить после текущего фрагмента |
| `POST /v1/jobs/{id}/resume` | `{}` → продолжить, пропуская готовое аудио |
| `GET /v1/jobs/{id}/audio` | Готовый аудиофайл; до завершения — HTTP 409 |
| `POST /v1/audio` | Синхронный вариант генерации: в ответе аудио |
| `POST /v1/server/stop` | `{}` → сохранить текущую работу и завершить сервер |

Состояния: `queued`, `running`, `completed`, `paused`, `error`.
Ошибки синтеза приостанавливают очередь и доступны в `error`; после устранения
причины её можно продолжить. После перезапуска незавершённые задания имеют
состояние `paused`. Сами проекты лежат в `api-data/jobs/{id}` и могут быть
открыты в GUI после завершения/остановки API-задания.

Ограничения длины TTS-модели к запросу целиком не применяются: текст делится
на фрагменты автоматически. Максимальный размер JSON-запроса — 64 МиБ.
Аудио объединяется последовательно; ожидание ручной проверки не требуется.
GUI и API делят очередь вычислений, поэтому одновременно модель выполняет
одно задание. Скачивание моделей не блокирует интерфейс.

## Генерация и настройки

Тело запроса: `text` (обязателен), `title`, `format` (`wav`, `mp3`, `flac`,
`m4a`, `m4b`), `settings`, необязательный `cover_id`.

Основные поля `settings`:

- `mode`: `simple` или `advanced`; простой режим не вызывает языковую модель.
- `engine`: `piper`, `piper-denis`, `piper-dmitri`, `piper-ruslan`, `higgs`.
  Выбранная модель должна быть установлена. Руслан скачивается через каталог.
- `max_chars`: 20–2400, по умолчанию 300; `pause_ms`: пауза между фрагментами.
- `temperature`, `top_p`: параметры Higgs; `language`: язык проверки речи (`ru`, `en`).
- `auto_cut_pauses`: искать длинные паузы; `max_pause_ms`: порог поиска.
- `pause_replacement_ms`: заменить найденную паузу тишиной этой длины.
  Значение 0 включает прежнее исключение с защитными краями по 40 мс;
  положительное значение задаёт точную длину заменяющей тишины.
- `text_processing`: настройки очистки и разбиения, как в `GET /v1/settings`.
- `llm_model`: `qwen2.5-1.5b`, `qwen2.5-3b`, `qwen2.5-7b`.
- `correct_text`: корректировать грамматику и смысловые ошибки в расширенном режиме.
- `dialogue`: назначать голоса персонажам в расширенном режиме.
- `voices`: список голосов с уникальными `id`, `description`, `engine`;
  для образца — `sample_id` и необязательный `reference_text`.

По умолчанию включён простой режим. Расширенный режим не изменяет исходный
текст: исправления и реплики сохраняются отдельно в проекте. ИИ может ошибаться
в смысле и определении говорящего; результаты и назначенные голоса доступны
для просмотра и правки через **Режим проекта / ИИ**.

## Несколько персонажей и образцы

Сначала загрузите образец:

```json
{"kind":"sample","extension":".wav","data":"BASE64_СОДЕРЖИМОГО_ФАЙЛА"}
```

Допустимы WAV/FLAC/MP3 длительностью до 120 секунд, размером до 32 МиБ.
Для обложки передайте `kind: "cover"`, расширение `.png`/`.jpg`/`.jpeg` и
Base64. Обложка — до 16 миллионов пикселей. Полученный ID используйте в
`sample_id` или `cover_id`. Пути к файлам компьютера API не принимает.

Пример расширенного запроса:

```json
{
  "text": "Анна сказала: «Добрый вечер». Иван ответил: «Здравствуйте!»",
  "format": "m4b",
  "cover_id": "ID_ЗАГРУЖЕННОЙ_КАРТИНКИ.png",
  "voice_count": 2,
  "settings": {
    "mode": "advanced",
    "llm_model": "qwen2.5-3b",
    "correct_text": true,
    "dialogue": true,
    "max_chars": 300,
    "auto_cut_pauses": true,
    "max_pause_ms": 1000,
    "pause_replacement_ms": 160,
    "voices": [
      {"id":"female","description":"Женский голос, рассказчик и Анна","engine":"piper"},
      {"id":"male","description":"Мужской голос Ивана","engine":"higgs",
       "sample_id":"ID_ЗАГРУЖЕННОГО_ОБРАЗЦА.wav","reference_text":"Точный текст образца"}
    ]
  }
}
```

При наличии образца для голоса используется Higgs. Его качество зависит от
языка и образца; для предсказуемой русской речи доступны три готовых Piper-голоса.
Можно обойтись без `voices`: передать `voice_count` и массив
`voice_descriptions` той же длины на верхнем уровне. Тогда используются разные
установленные Piper-голоса. Если их недостаточно, API попросит предоставить
голоса/образцы явно. Когда персонажей больше, чем голосов, ИИ может назначить
один голос нескольким персонажам. Итоговые назначения — в `characters` задания.

Текст озвучки и обложка встраиваются в поддерживаемые форматы. RF64 (WAV свыше
4 ГБ) сохраняется без этих метаданных. Отображение обложки зависит от плеера.

## Установка моделей

В поставку уже включены Higgs/codec, Whisper small, Piper Ирина/Денис/Дмитрий,
Qwen 2.5 1.5B и 3B. Для них интернет не нужен. Дополнительные модели требуют
интернета только во время загрузки. Программа поддерживает модели перечисленных
семейств из каталога, а не произвольные архитектуры Hugging Face.

Языковая модель использует GPU при наличии достаточной свободной видеопамяти;
иначе работает на CPU. Модели 3B/7B требуют больше памяти и времени, чем 1.5B.
Загрузка закрепляется на конкретной ревизии; лицензии моделей лежат рядом с
файлами весов. Источники: [Qwen](https://huggingface.co/Qwen),
[Piper voices](https://huggingface.co/rhasspy/piper-voices).


## Версия 0.7.0

В `settings` доступны: `retry_errors` (true), `error_retries` (10), `retry_low_score` (true), `min_score` (85), `quality_retries` (10). Лучший WAV сохраняется, очередь продолжает работу после исчерпания повторов.

Защитные края внутренних пауз: `pause_keep_start_ms`, `pause_keep_end_ms` (300). Краевые паузы: `trim_start_pause`, `trim_end_pause` (true); `start_pause_threshold_ms`, `end_pause_threshold_ms` (800); `start_pause_keep_start_ms` (50), `start_pause_keep_end_ms` (200), `end_pause_keep_start_ms` (200), `end_pause_keep_end_ms` (50).

`text_processing.replacements`: массив пар строк, например `[["ё", "е"], ["т. е.", "то есть"]]`. `text_processing.order`: перестановка `ai, roles, replace, symbols, cleanup, split`; `roles` должен предшествовать `split`. `remove_linebreaks` по умолчанию true; удаление переносов производится после разделения.

В расширенном режиме роли определяются до окончательной нарезки. `characters` в статусе завершённого задания содержит постоянные ID и сведения о персонажах. Без переданных голосов роли остаются без назначенного голоса; озвучка использует голос по умолчанию.
